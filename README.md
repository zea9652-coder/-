# -# 工作区长期指令（AGENTS.md）

> 与 `~/.dsh/AGENTS.md` 的全局指令叠加使用；冲突时以《工作总纲》与计划表为准。
> 本文件是长期约定，新增模块开工前请重读。

## 0. 依据优先级（任何设计冲突按此裁决）

**计划表 > 官方文档与公开规范 > 主流开源实现 > Legacy（仅作思路参考）**

## 1. 参考源定位

- `../欧美旅游集成平台部署/航班/` 与任一 GitHub 同类项目地位相同：**只读参考源之一**，只取构造精华（领域建模、状态机设计、业务流程组织），取完即止。
- 禁止把它设为任何形式的上级：不进目录层级、不作继承来源、不出现「父级项目」「以旧项目为准」「原项目标准」等表述。
- 引用它必须三段式：**借鉴了什么 → 为什么这个设计好（外部依据）→ 结合本项目做了什么改造**；缺一段视为未引用。
- 不修改、不覆盖、不删除 `航班/` 下任何文件；上一会话的存档目录 `欧美旅游集成平台部署/ota-platform/` 勿动（非本项目基线）。

## 2. 研究义务（模块动工前）

1. 顺序：官方文档 → 协议/行业标准 → 同类开源实现（官方维护或高 star）→ 技术博客（仅作线索）→ 最后才看 Legacy。
2. 原始抓取存 `docs/evidence/<module-id>/`（URL + 抓取时间 + sha256）；工具：`node scripts/evidence/fetch.mjs --module <id> --url <url> --slug <s> --note "<说明>"`。
3. 产出 `docs/design/<module-id>.md`（模板 `docs/design/_TEMPLATE.md`），并在 `docs/design/index.json` 登记状态。
4. 外部做法优于 Legacy 时**必须采用外部做法**；查不到写「未确认」，禁止编造。
5. 调研未完成的模块不得进入实现——`pnpm gate:research` 会拒绝（`status` 进入 `design-ready` 起受约束）。

## 3. 交付标准：超越，不是复刻

- 合格线：**新项目有 Legacy 拿不出的东西**。交付前自答两问：① 该模块去掉后，Legacy 加一点优化能否顶上？② 新项目拿出了什么（架构 / 协议 / 开源组件 / 判据）？
- 借鉴必须转为本项目原生实现（自己的目录、命名、抽象）；禁止整体搬运目录结构或逐文件翻译。
- 存量代码按《工作总纲》§二.3 继续维护，不因本文件推翻或重写。

## 4. 命令

```bash
pnpm gate:all     # 定位表述 + 证据链 + 研究齐备 + 负向对照
pnpm ci:local     # 与 CI 逐条一致的本地复跑（含 governance 段）
```
